## 第二阶段：T5–T6

自行设计数据结构和补充测试，不调用现成的 CKY 或句法分析器代替实现。本实验使用二叉短语规则和词汇规则，不要求扩展到一般 CFG、PCFG 或概率最优树。

### T5：保存回溯路径

将识别表扩展为可恢复句法树的表。词汇单元记录终结词；其他单元记录左右子节点的符号、跨度及切分点。**同一跨度中的同一非终结符（non-terminals）须保留所有不同的回溯路径**，不能只保留第一条，否则无法完成全部树的枚举。

展示示例句的根单元及至少一个内部单元。

### T6：递归生成句法树

- 实现 `build_tree`，从起始符号恢复一棵完整树，用嵌套 tuple 或括号表示输出。
- 实现 `build_tree_full`，遍历所有回溯路径，组合左右子树，返回全部不同的句法树。
- 无法识别的输入须明确返回无树结果（如单树返回 `None`、全部树返回 `[]`），不因根节点不存在而报错。

**至少保留以下测试及输出：**

| 输入 | 检查内容 |
| --- | --- |
| `flights from miami to cleveland .` | 可识别；树根为 `TOP`，叶子按顺序还原输入，每个节点符合文法规则。 |
| `miami flights cleveland from to .` | 不可识别；不生成树。 |
| 含文法外词的句子 | 不可识别；不生成树，程序不报错。 |
| 空 token 列表 | 返回 `False`，不生成树。 |
| 自建歧义文法：起始符号 `S`，规则 `S -> S S`、`S -> a`；输入 `a a a` | `build_tree_full` 恰好输出两棵不同的树，叶子均为 `a a a`。 |

歧义测试用于检查“全部树”，不能只用“成功输出一棵树”作为通过标准。不同实现的符号顺序、树输出顺序可以不同。
